# vocab

Английский в одном Telegram-боте (@workbookonlinebot), два раздела:

- **Тетрадь** — 134 упражнения по грамматике из Work book учителя: времена,
  Passive, Conditionals, Relative clauses, Gerund, модальные глаголы,
  времена инфинитива, Participle, союзы. Ошибка не «неверно», а разбор:
  не то время, потерялся will, нужна V3. Учитель видит ошибки учеников
  и шлёт классу свои тесты с пропусками.
- **Слова** — SRS. Пришёл в бот с любой формой слова — went, children,
  reading — получил лемму, форму, перевод и примеры, а слово вернулось на
  повторение ровно тогда, когда почти забылось.

Бот публичный: входа нет, пользователь — это его Telegram ID. Словарь общий
на всех, расписание и статистика у каждого свои.

Раньше тетрадь была отдельным мини-аппом (репозиторий `grammar`) с
прогрессом в Telegram CloudStorage. Теперь она здесь, прогресс в базе;
при первом открытии мини-апп сам переносит старый прогресс из CloudStorage
(`POST /grammar/import`, повтор безопасен).

Алгоритм повторений — FSRS (`py-fsrs`). Anki не используется ни в каком виде.

## Из чего состоит

| Часть | Стек | Роль |
|---|---|---|
| API | FastAPI + asyncpg | словарь, карточки, планировщик, отдача мини-аппа и `/mcp` |
| БД | PostgreSQL 17 | всё состояние |
| Бот | aiogram 3 + APScheduler | добавление слов, напоминания, вход в мини-апп |
| Mini App | React 18 + TypeScript + `@telegram-apps/telegram-ui` | меню, карточки, 7 видов тестов, серия и XP, рейтинг недели, админка |
| MCP | fastmcp, смонтирован в API | доступ из LibreChat / Claude |
| Лемматизация | `lemminflect` + `wordfreq`, офлайн | форма → лемма, частотность |
| Обогащение | OpenAI-совместимая LLM (боевой — Qwen 3.8 на 10.40.9.47:8010) | перевод, формы, примеры, поиск фраз |
| Быстрый ввод | bookmarklet + расширение MV3 | добавление с компа |

Контейнеров три: `db`, `api`, `bot`. Отдельного веб-сервера со статикой нет —
собранный мини-апп лежит внутри пакета `vocab` и отдаётся тем же приложением,
что и API. Своего Caddy тоже нет: публичный домен и TLS даёт **NetBird
Reverse Proxy**, до контейнера он ходит по оверлею.

## Запуск

```sh
cp .env.example .env
netbird status -d | grep "NetBird IP"   # адрес этой машины → BIND_ADDR
make env-check                          # ни один обязательный ключ не пуст
make up
```

`api` слушает только на `BIND_ADDR` (адрес 100.x.x.x в оверлее). Публичного
порта у него нет — снаружи до него достаёт исключительно reverse proxy
NetBird.

### Сервис в NetBird

Reverse Proxy → Services → Add Service:

| Поле | Значение |
|---|---|
| Domain | `vocab.proxy.blick.uz` (совпадает с `DOMAIN` в `.env`) |
| Type | HTTPS |
| Resource | пир, на котором стоит vocab |
| Location | `/` |
| Destination | `http://<BIND_ADDR>:8000` |

**Auth & Access оставить выключенными.** Мини-апп открывается во встроенном
браузере Telegram, и SSO NetBird там не пройти. Доступ закрывает само
приложение: подпись initData для мини-аппа, `X-Token` для расширения
и MCP — без них любой запрос получает 401.

Дальше в @BotFather один раз указать домен мини-аппа (`/setdomain`), иначе
Telegram не откроет `https://DOMAIN/app/`.

Проверка живого контура:

```sh
API_TOKEN=... SMOKE_BASE=https://DOMAIN make smoke
```

### Боевой сервер

Сейчас vocab живёт на `test_moe` в `~/vocab` — это git-клон, `.env` лежит
только там. Публичный адрес — `https://elearn.tpp.uz/vocab/app/`: nginx
elearn.tpp.uz держит TLS и проксирует на `:80` сервера, там Traefik гейтвея
sarmoni (репо SarMoni, `infra/gateway`) срезает `/vocab` и отдаёт в `api`.
Наружу открыты только статика `/vocab/app/` и запросы с заголовком
`X-Init-Data`; `X-Token`, `/mcp` и `/internal` снаружи недоступны.
Поэтому в `.env` сервера `DOMAIN=elearn.tpp.uz/vocab`,
`BIND_ADDR=127.0.0.1` и `COMPOSE_FILE=docker-compose.yml:docker-compose.edge.yml`
(второй файл подключает `api` к сети гейтвея), NetBird не нужен. Бот — @workbookonlinebot
(до объединения с тетрадью был @vocab_srs_bot; данные привязаны к Telegram
ID, поэтому смена `BOT_TOKEN` ничего не теряет).

Выкатка — только через git, правки руками на сервере затрёт следующий pull:

```sh
git push origin main
make deploy        # git pull --ff-only + docker compose up -d --build
```

## Тетрадь

Задания — `backend/src/vocab/grammar/content.json`, отдаются только из
Telegram (`GET /grammar/content`, с ETag): это книга учителя, в статику она
не кладётся. Ключи ответов в контенте не хранятся — их строит движок
`miniapp/src/features/grammar/engine.ts` из кода пропуска:

```
I {|to take|C1} my brother.          → am taking   (время C, лицо 1)
{You ever|to try|HP} sushi?          → have you ever tried
If I {|be|D1=were} you…              → ручной ответ
The woman {||=who|that} helped me.   → варианты через «|»
```

Времена: S, C, F, D, W (Past Cont.), H (Present Perfect), R (PP Cont.),
X (Past Perfect), K (would + V0), L (would have + V3); лицо 1 / 3 / P.
Так ключ и разбор ошибки не расходятся: «am take» — «Нет формы -ing»,
ответ в другом времени упражнения — «Не то время, yesterday — Past Simple».

Проверка всех 2309 заданий перед выкаткой контента — движок обязан принять
свой ответ и не принять ответ в чужом времени:

```sh
cd miniapp && node scripts/grammar-keys.ts           # ключи глазами
cd miniapp && node scripts/grammar-keys.ts --quiet   # только проверка
```

Итог задания (`POST /grammar/attempts`) пишет результат, каждую неверную
попытку с разбором и продлевает серию; решённое задание даёт XP в рейтинге
недели наравне с повторением слова. PDF с ответами бот присылает ученику в
чат (`POST /grammar/pdf`, шрифты DejaVu в образе).

## Учителя

Учитель видит ошибки всех учеников тетради: что ввёл, почему неверно, чем
кончилось, и где ошибается класс. Если ответ верный, а ключ его не знал,
учитель жмёт «Засчитать» — ответ принимается у всех, у ученика задание
перестаёт считаться ошибкой.

Назначает админ (`OWNER_TG_ID`, `ADMIN_TG_IDS`): `/teacher` в боте даёт
одноразовую ссылку `t.me/<bot>?start=teach_<code>` на 7 дней и список
учителей с кнопкой «Снять». Учитель открывает ссылку — и у него появляются
раздел «Ученики» в мини-аппе и `/students` в боте.

### Тесты учителя

Во вкладке «Тесты» раздела «Ученики» учитель создаёт класс и пересылает
ученикам его ссылку `t.me/<bot>?start=class_<code>`: кто открыл, тот
в классе. Тест уходит классу: бот пишет каждому с кнопкой «Открыть тест»,
за день до срока не сдавшим напоминает (`remind-tests`, вечерний час).

Вопрос — строка с ответом в квадратных скобках, подсказка в круглых:
`She [doesn't like] (not like) coffee.`, несколько верных — через `|`.
Сокращения сравниваются развёрнутыми (`classwork.norm`, тот же, что `norm`
тетради): `don't` = `do not`, `I've` = `I have`. `'s` и `'d` не
раскрываются — is/has и would/had правило не угадает. Готовую контрольную
(текст или .docx) ИИ переводит в такие строки
(`POST /teacher/tests/convert`) и помечает, где ответ подставил сам.

Попытка одна. Проверяет сервер: до срока ученик не получает ключ, видит
только свои ответы; после срока — балл и правильные ответы. Балл не
хранится, а считается при чтении: «Засчитать» у учителя меняет его у всех,
кто ответил так же.

## Как это работает

**Общий словарь и личные карточки.** `words` — одна строка на лемму:
перевод, IPA, формы (`go · went · gone`), признак неправильности, примеры,
частота Zipf. `cards` — только расписание FSRS конкретного пользователя
и ссылка на слово.

**Добавление.** `POST /words` с одним словом:

1. `wordfreq` отсекает то, чего в английском нет (`asdfg` → 422, ИИ не зовётся);
   опечатку, которую `wordfreq` знает из веба (`helf`, `thier`), ловит
   `lexicon.suggest`: слова нет в словаре `lemminflect`, а на расстоянии одной
   правки есть намного более частое. Ответ — 422 с `suggestion`, бот
   предлагает «➕ help» и «Нет, именно helf» (`as_is`);
2. `lemminflect` приводит форму к лемме и называет её:
   `went` → go, «прошедшее время (V2)»; `reading` → read, «форма на -ing»;
3. лемма есть в `words` — ответ сразу из базы; нет — один запрос к DeepSeek
   (с одним повтором), и результат сохраняется для всех;
4. заводится карточка, ответ содержит всё сразу — бот ничего не ждёт фоном.

Несколько слов — предложение целиком не учится: DeepSeek достаёт из него
устойчивые выражения (`gave up` → give up, `more and more`), и каждое
проходит шаг 3.

Запросы к ИИ ограничены `LLM_DAILY_LIMIT` (по умолчанию 30) на человека
в день. Слова, которые уже есть в общем словаре, лимит не тратят.

**Рейтинг слова** виден в ответе бота, на карточке в мини-аппе и в `/top`:
место по частоте в языке («топ-100», «топ-5000») и сколько людей слово
учат. Частота — шкала Zipf из `wordfreq` (данные Википедии, субтитров,
книг, новостей, веба), log10 употреблений на миллиард слов. Место — позиция
среди ~45 тысяч лемм, собранных при старте API из 60 тысяч самых частых
словоформ (около 2 секунд): go — №45, read — №215, reliable — №3835. Для слова суммируются все формы
(go + went + gone + going + goes), иначе неправильные глаголы занижены.
Для фраз `wordfreq` выдумывает частоту из отдельных слов («up give» =
«give up»), поэтому их оценивает модель в том же запросе, что и перевод.

Удаления у пользователей нет. Мусор из общего словаря владелец убирает
командой `/ban слово` в боте — слово помечается `banned` и пропадает
из всех очередей.

**Новые слова.** Свои карточки кончились — мини-апп предлагает «Давай»,
и `POST /discover` заводит 10 карточек из общего словаря: сначала слова,
которые учат больше людей, потом самые частые в языке.
Новых в день — не больше 15, считая свои (`NEW_PER_DAY`): после 41 за день
назавтра забывалась четверть. Слова с общим переводом (postpone и put off)
очередь и тесты не ставят подряд — рядом они путаются.

**Оценка теста.** Выбор из вариантов (перевод, слово, пары, на слух, опрос
в чате) за верный ответ ставит Hard, а не Good: узнать — не вспомнить.
Good дают только тесты на припоминание — написание, пропуск, формы.
В `reviews.mode` пишется, чем дана оценка: так видно, какими режимами
пользуются.

**Забываемое слово.** От 4 «не помню» карточка просит свою зацепку —
созвучие или фразу про себя; она хранится в `cards.note` и дальше видна
на обороте.

**Кнопки карточки.** «Не помню» — FSRS Again, «Помню» — Good (под кнопкой
срок, когда слово вернётся: `remembered_due` в карточке), «Знаю» —
`PUT /cards/{id}/known`: отметка `known_at` убирает карточку из повторения,
тестов, прогноза и напоминаний, расписание не трогает. Снекбар «Отменить»
шлёт `DELETE` той же ручки.

**Повторение.** `GET /queue` отдаёт до 50 карточек с `due <= now()`. Мини-апп грузит очередь один раз, оценки шлёт по одной
и меняет карточку сразу, не дожидаясь ответа. `POST /review` перекладывает
поля в `py-fsrs`, получает новое расписание и пишет строку в `reviews` —
одной транзакцией. `reviews` нужен не UI, а будущему дообучению параметров
через `fsrs.Optimizer`.

**Тесты.** Мини-апп открывается меню: карточки и семь тестов —
выбор перевода (EN→RU), выбор слова (RU→EN), пары, на слух (озвучка
браузером, `speechSynthesis`), написание слова, пропуск в примере,
неправильные глаголы. `GET /quiz` отдаёт до 10 уже виденных карточек
(сначала те, что пора повторять) вместе с вариантами ответа: варианты
собирает сервер (`quiz.py`) — той же части речи, без синонимов с общим
значением. Пропуск ищется в примерах по всем формам слова (`went` для go,
`gave up` для give up).

Оценку в тесте ставит проверка, а не человек, и уходит она обычным
`POST /review`: верно — Good, опечатка в одну букву, подсказка или лемма
вместо формы — Hard, ошибка — Again. Easy тест не ставит. В боте то же
самое — `/quiz`, quiz-опросы Telegram с вариантами от того же `/quiz`.

**Жалобы и админка.** Под каждым словом в боте и на обороте карточки
в мини-аппе — «⚠️ Ошибка в слове»: опечатка, перевод, пример, другое. Одна
открытая жалоба от человека на слово. Админы (`OWNER_TG_ID` и
`ADMIN_TG_IDS`) видят в меню «Админку»: сводку, слова с жалобами (править,
в бан, отклонить) и поиск по всему словарю с правкой перевода, IPA, форм,
уровня и примеров. Любое решение по слову закрывает жалобы на него.
Лемму и часть речи править нельзя — на них ссылаются карточки.

**Геймификация.** Каждое повторение — 10 XP и день в серию (🔥 дней
подряд хотя бы с одним повторением; рекорд хранится отдельно). `/rating` в боте
и кнопка 🏆 в мини-аппе — рейтинг недели по XP с понедельника: неделя, а не всё время, чтобы новичку
было за что бороться. Имя в рейтинге — `first_name` из initData мини-аппа,
другие пользователи его видят.

После сессии мини-апп показывает XP за неё, серию, XP за неделю и место.
Статистику он запрашивает только после того, как все оценки доехали до
сервера: оценки уходят фоном, и без ожидания цифры отставали бы на последнюю.

**Напоминания.** APScheduler в процессе бота, в часы `REMINDER_HOURS`
(по умолчанию 09:00 и 20:00 по `TZ`). Пишут только тем, кто сегодня ещё
не занимался:

- серия под угрозой — утром «сегодня ещё не занимался», в последний час
  дня «серия сгорит в полночь»;
- серия потеряна — по одному сообщению на 2, 3, 7 и 14 день, только утром;
  после 14 дней — тишина;
- ни разу не повторял — утром, если есть слова на повторение.

Список бот берёт у API (`GET /internal/reminders`), а текст выбирает сам;
в базу не ходит: схему знает только API. День считается по общему `TZ`.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/words` | `{word}` → леммы, перевод, формы; карточки заводятся |
| GET | `/queue` | что повторять сейчас |
| POST | `/discover` | 10 новых слов из общего словаря сразу карточками |
| POST | `/review` | `{card_id, rating}` (1..4) → новое расписание |
| GET | `/stats` | всего / выучено / due сегодня / прогноз на 7 дней / серия |
| GET | `/words/top?limit=` | рейтинг общего словаря, с отметкой «есть у меня» |
| GET | `/words/search?q=` | поиск (для MCP) |
| GET | `/words/weak?limit=` | где чаще всего сыплюсь (для MCP) |
| GET | `/leaderboard` | рейтинг недели по XP и своё место |
| GET | `/quiz?mode=any\|irregular\|cloze&limit=` | карточки для теста с вариантами и пропуском |
| POST | `/reports` | `{word_id, reason}` жалоба на слово |
| GET | `/me` | `{is_admin}` — показывать ли админку |
| GET | `/admin/summary` | люди, активные за неделю, слова, бан, открытые жалобы |
| GET | `/admin/reports` | слова с открытыми жалобами |
| POST | `/admin/reports/{word_id}/dismiss` | отклонить жалобы |
| GET | `/admin/words?q=` | поиск по всему словарю, с забаненными |
| PUT | `/admin/words/{id}` | правка слова, закрывает жалобы |
| GET | `/internal/reminders` | кто сегодня не занимался: серия, дни пропуска (только по токену) |
| POST | `/internal/ban` | `{word}` убрать из общего словаря (только по токену) |

Аутентификация — два пути, оба заголовками:

- мини-апп присылает `X-Init-Data` с initData Telegram, подпись проверяется
  HMAC-SHA256 ключом бота плюс проверка возраста (24 часа);
- бот присылает `X-Token` и `X-Tg-Id` того, кто ему пишет;
- расширение, букмарклет и MCP присылают `X-Token` из `.env` и работают
  от владельца (`OWNER_TG_ID`).

Заголовка нет вовсе — 401.

## MCP

Смонтирован в то же приложение: `https://DOMAIN/mcp/`, транспорт HTTP,
авторизация `Authorization: Bearer <API_TOKEN>`.

fastmcp сверяет заголовок `Host` со значением `DOMAIN`. Если reverse proxy
подставляет туда адрес пира вместо публичного имени, `/mcp` ответит отказом —
чинится там же, в `mcp/server.py`, параметром `allowed_hosts`.

```json
{
  "mcpServers": {
    "vocab": {
      "url": "https://DOMAIN/mcp/",
      "headers": { "Authorization": "Bearer <API_TOKEN>" }
    }
  }
}
```

Тулы: `add_word`, `due_count`, `search_words`, `weak_cards`.

## Быстрый ввод с компа

Букмарклет собирается из `.env`, чтобы токен не попал в репозиторий:

```sh
python3 scripts/bookmarklet.py
```

Вывод — в закладку.

Расширение (`extension/`) собрано под оба движка: в манифесте объявлены
и `service_worker` (Chrome), и `background.scripts` (Firefox), а `browser.*`
и `chrome.*` разводятся одной строкой. Адрес и токен вводятся на странице
настроек, в код они не попадают.

- Chrome: `chrome://extensions` → Developer mode → «Загрузить распакованное»
- Firefox и форки (Zen): `about:debugging#/runtime/this-firefox` →
  «Load Temporary Add-on» → выбрать `manifest.json`. Временная установка
  живёт до перезапуска браузера; постоянная требует подписи на
  addons.mozilla.org.

## Разработка

```sh
make front        # пересобрать мини-апп локально
make test         # тесты backend
cd miniapp && npm run dev   # vite с проксированием API на localhost:8000
```

Тестов намеренно мало: проверяются подпись initData и перекладывание полей
FSRS — то, что ломается молча. Остальное покрывает `make smoke` на живом
контуре.

## Границы, которые не двигаются

- **Миграции не правятся после применения.** Схема существующей базы и базы
  с нуля разъедутся молча. Изменение схемы — новый файл в
  `backend/src/vocab/migrations/`.
- **Ключ задания тетради — «упражнение-индекс» (`15-2`).** На нём держатся
  прогресс, ошибки и засчитанные ответы. Задания в упражнении не
  переставляются и не удаляются из середины — только дописываются в конец.
- **`.env` не коммитится, `.env.example` коммитится и обязан быть полным.**
  Пустое значение в шаблоне означает «заполнить обязательно».
- **В базу ходит только API.** Бот и MCP — такие же HTTP-клиенты, как
  расширение. Иначе схему пришлось бы знать трём процессам, а обогащение
  запускать в каждом заново.
- **Запросы к ИИ ограничены `LLM_DAILY_LIMIT` на человека.** Бот публичный,
  а модель общая; слова из общего словаря лимит не тратят.
- **`api` не биндится на `0.0.0.0`.** Единственный вход снаружи — reverse
  proxy NetBird. Публичный порт открыл бы API в обход оверлея.

## Чего в MVP нет

Своё аудио (озвучка только браузерная), несколько колод, импорт `.apkg`, офлайн-режим,
редактирование карточек из UI, настройки алгоритма, регистрация
пользователей. Каждый пункт добавляется после того, как система прожила
месяц в реальном использовании.

## Критерий готовности

Через неделю: минимум 100 добавленных слов и 5 дней повторений подряд.
Если этого нет — проблема не в коде.
